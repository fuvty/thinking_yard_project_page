# 页面多语言维护

先读 [内容规范](design-system/content.md)。英文为默认版本，中文独立输出；不自动重定向。导航上方的提示、页脚语言链接、缺失译文提示和本地偏好共用 `shared/language/`，沿用原有偏好存储键，避免重复提示。

## 设计依据与本项目的选择

参考 Apple 官方 [Localization](https://developer.apple.com/localization/)、[Writing](https://developer.apple.com/design/human-interface-guidelines/writing) 和 [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)（2026-10-29 核对）。Apple 强调文案与代码分离、提供翻译上下文、保持信息层级，以及针对语言和设备核验可读性、截断与布局。这里将这些原则落实到研究网页，并不照搬原生应用的字体尺寸或营销文案。

写作、强调语义与数字口径统一遵循 [内容规范](design-system/content.md)，此处维护实现与验收规则。以下选择适用于本项目，不宣称是 Apple 对网站的硬性规定。

## 中文排版实现

先检查措辞和容器宽度，再选择最少的排版约束。不照抄英文 `<br>`，不逐行硬编码中文，不为塞下译文而缩小字号。

| 内容 | 共享处理 | 边界 |
| --- | --- | --- |
| 标题、首屏短引言 | `text-wrap: balance`；必要时用 `.i18n-phrase` 标记短语意单元 | 均衡行宽不等于语意自然，例如不能把“自己”拆成“自／己”。短语在过窄或放大时仍可内部换行；不要求所有标题分成两行 |
| 普通段落 | 自然流式布局，`text-wrap: pretty` 渐进改善尾行 | 不逐句包裹短语，不为保护所有词组制造大段留白 |
| 短术语、模型名、数值与单位 | 必要时用 `.i18n-nowrap`，如 `KV cache`、`R1-14B`、`1.7 个百分点` | 不保护整句或长短语；先确认在窄屏和文字放大后仍能容纳 |
| 机构列表 | `.i18n-affiliations` 自动折行 | 每所机构保持完整，不用连续空格和 `<br>` 模拟列 |

字体与行距见 [视觉基础](design-system/foundations.md#typography)，实现集中在 `shared/styles/tokens.css` 与 `shared/language/styles.css`。`line-break: strict` 处理中文标点禁则。排版不要求在所有宽度下断行相同；人工检查孤立尾字、关键短语、孤立标点和内容重叠。

## 路径和资源

URL 采用语言前缀：英文保留根路径，中文位于 `/zh/` 之下。这与已有中文首页一致，便于未来统一路由、站点地图和语言链接。Apple 的 [英国站](https://www.apple.com/uk/mac/) 使用地区前缀，其中国站也使用独立域名；这些是实现例子，不是必须遵守的 URL 标准。我们按语言组织，不照搬国家/市场划分。旧 `/projects/<slug>/zh/` 只做兼容跳转，不生成第二份内容；跳转保留查询和章节 hash，canonical 与 hreflang 只使用正式地址。

- 首页：`/` 与 `/zh/`。
- 项目：`/projects/<slug>/` 与 `/zh/projects/<slug>/`。所有项目都生成这两个地址。在 `config/projects.json` 中以 `"locales": ["zh"]` 标记真实中文译文的可用性，不用它决定站点语言。
- 章节 ID 在两种语言中相同；切换语言保留查询参数和当前 hash。中文站点中的所有项目链接都保持 `/zh/projects/.../`。正文无译文时使用英文，站点导航仍为中文。中文页面的 Home 指向中文首页。
- `static/` 只有一份，中文页不复制资源、数据、脚本或图表逻辑。构建器将模板里的 `static/` 和 `./static/` 改成项目根路径。外部脚本使用 `SiteI18n.asset('./static/...')` 解析相对页面的资源；模块相对 `import.meta.url` 的路径无需修改。

## 站点语言与正文语言分开

| 状态 | 导航、Home 与项目链接 | 正文 | 页脚语言选择 | 顶部提示 |
| --- | --- | --- | --- | --- |
| 英文站点 | 英文站点 | 英文 | 有译文则中文可点，否则标为暂未提供；English 为当前 | 仅在有中文译文且浏览器偏好中文、未作选择时建议切换 |
| 中文站点，有译文 | 中文站点 | 中文 | 中文为当前，English 可点 | 无 |
| 中文站点，无译文 | 中文站点 | 英文 | 中文暂不可用，English 可点并切到英文站点 | 本次浏览首次打开该项目提示“此页暂无中文版，已显示英文版。”，滚动超过 8px 或点关闭后收起 |

- 兼容英文页面不是中文版，不把它标成 `hreflang=zh-CN` 的真实翻译，不加入中文 sitemap。其 canonical 指向英文原版，设 `noindex,follow`，但站内链接与地址保留中文上下文。
- HTML 的语言标记反映中文站点界面，正文容器单独标记 `lang="en"`；排版规则依据元素实际语言选择，不能让中文样式误作用于回退的英文正文。
- 语言栏与全局导航采用相同的 44px 高度；桌面和手机都用紧凑横排，文案长度必须在窄屏核验。文字放大时优先保证可读性。切换提示使用蓝色“切换中文”和次要色“Keep English”，不在相邻操作之间添加方向箭头。
- 缺失译文提示的已读状态按项目存入 sessionStorage，在当前标签页浏览会话中不重复；再次打开另一个无译文项目仍提示。它不修改用户的站点语言偏好。禁用存储时仍能关闭，禁用 JavaScript 时页脚状态及链接仍可用。
- 新增译文只需词典和注册可用性：同一个中文地址自动改为中文正文，提示与禁用状态自动消失。不要为每个项目另写兼容逻辑。

## 一份模板，两种文案

保留英文 `content.html` 作为唯一结构模板。每个项目新增 `locales/zh.json`：

```json
{
  "page": {
    "title": "项目名 · 中文标题",
    "description": "中文摘要",
    "sections": {"overview": {"label": "概览", "description": "本节简介"}}
  },
  "html": {"hero.subtitle": "自然的中文说明，可包含 <strong>必要强调</strong>。"},
  "attributes": {"hero.figure": {"alt": "图片说明"}},
  "runtime": {"Play": "播放", "Request {number}": "请求 {number}"}
}
```

- 在模板的完整文案块上加 `data-i18n="hero.subtitle"`。构建时用 `html` 中的值替换其内部 HTML；英文输出保持原文。
- 在需要翻译属性的元素上加 `data-i18n-attrs="hero.figure"`，支持 alt、title、aria-label、placeholder。
- 以完整段落为翻译单元，避免拆成词语后机械拼接。只替换文案，不给含表单、控件或动画节点的大容器加整块替换；保留内部需要的 span、类名、ID 和数据属性。
- 目录翻译以章节 ID 为键；不改 ID、group、顺序。项目名、作者名、论文题目、BibTeX、模型名、数据集名、公式、实际输入输出和代码原样保留。数字不因翻译自行变化；论文核对发现的事实修订须同步中英文。论文图片不重画，周围正文及图注中文化。
- 重要的加粗、强调色和局部渐变用 `data-emphasis="概念标识"` 标记；译文保留标识和对应概念，可调整语序。复杂文案在模板中简短说明比较对象或语境。构建检查文案键和标识的完整性，人工核对实际词义；标签一致不能证明语义正确。增删文案块时同步维护词典，不复制完整中文 HTML。

## 动态内容

项目脚本从共享运行时取翻译：

```js
const {t} = globalThis.SiteI18n;
button.textContent = t(paused ? 'Play' : 'Pause');
counter.textContent = t('Request {number}', {number: index + 1});
```

`runtime` 使用完整英文字符串为键，以免为每个项目维护第二套英文词典。生成器保证运行时先加载再运行项目脚本；缺失键由共享运行时回退英文，页面脚本无需复制插值或回退实现。文字标记仍需要按输出方式正确转义，不能把外部数据当 HTML。

翻译按钮、筛选器、空状态、状态说明、图表坐标轴和无障碍说明，包括暂停、切换等操作后才出现的文字，以及 CSS 伪元素生成的提示；这些文字同样由词典提供。不要翻译真实模型响应、实验输入或 JSON API 字段。图表与演示的计算、时序和数据来源保持不变。

## 验收流程

1. **事实与强调。** 对照中英文及论文来源，核对数字、单位、基线、限定条件和所有局部强调；同时检查首页、正文与动态摘要。
2. **独立阅读。** 单独读中文，确认自然、清晰、信息完整；再读英文。不能只看词句是否一一对应，也不统一压缩篇幅。
3. **实际排版。** 检查 1440px、约 768px、390px、320px，以及文字放大后的效果。重点看首屏、长标题、数值单位、按钮、表格、SVG/Canvas 动态文字；以实际渲染为准，不以源码中没有 `<br>` 或构建通过代替验收。
4. **交互与回退。** 复核章节和资源、语言提示、跨项目链接、缺失译文页面、动态控件及无 JavaScript 时的内容。实验数据与 API 示例不因翻译变化。

共享路由、样式和生成器由集成人员维护；如使用子任务，各子任务只编辑负责的项目源文件。构建与测试统一运行，避免并行写生成目录。报告实际检查范围及剩余问题。

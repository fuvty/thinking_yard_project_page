# C2C / R2R 论文与网页核对

核对日期：2026-10-29。网页中英文同步维护；论文版本以 arXiv 的 submission history 为准。

## C2C

- 最新版：[arXiv:2510.03215v2](https://arxiv.org/abs/2510.03215v2)，2026-03-02。
- `projects/c2c/static/data/performance_general.csv` 的 12 组结果、120 个准确率与时间数据逐项与 [表 4](https://arxiv.org/html/2510.03215v2#S4.T4) 一致，无需替换原始数据。
- 原首页 +10.5% / +5.0% 未标明统计范围。改用同一组可复核的主实验：Qwen3-0.6B Receiver + Qwen2.5-0.5B Sharer，四项基准平均。准确率相较 Receiver 增加 11.00 个百分点，相较 T2T 增加 5.355 个百分点（页面四舍五入为 5.4），延迟加速比 3.46×。
- 准确率差值一律以 pp / 百分点标示，不与相对百分比混淆。
- 按 §4.2，延迟加速比为平均 T2T 延迟 / 平均 C2C 延迟。例如 4.84/1.40 = 3.457。原交互摘要对各行加速比取算术平均，与论文的聚合方式不同，现已统一。全部 12 行为 30.47/4.87 = 6.257；不可把这个值解释为任意模型组合的通用加速比。
- 论文摘要仍写 6.4–14.2%、3.1–5.4%、平均 2.5×，它与 §4.2 / 表 4 的具体设置不是同一组可直接复算的汇总。网页采用明确的表 4 示例，不宣称摘要数字错误，也不混用统计范围。
- 方法表述补充残差融合：投影与融合结果通过门控加入 Receiver 原有缓存，并非直接覆盖。模型保持冻结，仅训练融合模块。跨模型使用需要 token / layer alignment 和训练，不暗示任意模型开箱即用。
- 泛化、LongBench、门控行为等新增论述可在未来扩展内容时引用；当前页面不堆砌所有附录结果。

## R2R

- 最新版：[arXiv:2505.21600v2](https://arxiv.org/abs/2505.21600v2)，2025-11-05。
- 现有准确率表和摘要的 46% / 5.6B，以及 R1-7B 28%、R1-14B 43%、R1-32B 50%，与表 2 一致。5.6B 是跨基准的平均激活参数量，非每个基准相同：AIME 5.5B、LiveCodeBench 5.1B、GPQA 6.3B。
- **生成速度与请求延迟分开。** [表 3](https://arxiv.org/html/2505.21600v2#S5.T3) 的 R2R 为 84.3 token/s，R1-32B 为 30.5 token/s，比值 2.76，约 2.8×。平均请求延迟是 218s 与 498s，比值 2.28×。二者因输出长度不同不能互换。网站保留 2.8×，明确标签为生成速度，并在结果区给出硬件与两个指标。
- 上述速度测试为 AIME、两张 A800-80GB、SGLang。主准确率实验为 AIME 2024–2025、GPQA-Diamond、LiveCodeBench 2024-08–2025-01，温度 0、最多 32K 输出 token。
- 89% / 6% / 5% 是 7.6M-token 训练集上、同一 LLM 上下文下的预测分类分布，并非部署的大模型调用率。主实验调用率为 11–15%；它由神经路由器的预测及阈值决定。
- 离线流程按句子边界续写并验证；大模型参考续写直接复用原回答。在线路由器只用小模型特征预测分歧，不能把离线 verifier 或理想 full-path 保证说成在线行为。
- Cost 是激活参数量乘输出 token 数的解码成本代理指标，包括 SLM、router 和加权 LLM 参数，不是实测延迟、总 FLOPs 或费用。3.8× 输出熵差异是相关性；低频 token 的原因保留推测而非因果断言。
- 网页的工作流是教学示意，静态 `sampleTokens` 不是本次 arXiv 核验得出的完整实验轨迹；本轮未改原模型示例数据。后续如替换该演示，应使用可追溯原始 token trace，避免从措辞单独判断推理分歧。
